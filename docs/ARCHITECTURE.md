# Architecture and conventions

Read this before adding a page or component. It explains how the pieces fit and the rules that keep the code
consistent. For visual details (measurements, colours, animations) use `research/DESIGN-SPEC.md`.

## 1. Data flow

```
research/*.json ──(generate-data.mjs, one-off)──> src/data/*.ts ──> src/lib/*.ts ──> pages/components
```

- **`src/data/`** holds typed content: `puppies.ts`, `happyFamilies.ts`, `faqs.ts`, `siteConfig.ts` (brand,
  contact details, socials, navigation), `pageMeta.ts` (title/description per route), `puppyFilters.ts`.
- **`src/types/`** defines the shapes (`Puppy`, `PuppyMedia`, `HappyFamilyPhoto`).
- **`src/lib/`** is the only layer pages should talk to for data. `lib/puppies.ts` exposes
  `getAvailablePuppies`, `getGoneHomePuppies`, `getPuppyBySlug`, `filterPuppies`, `getAdjacentPuppies`,
  `getCoverImage`, `getPuppyMetadata` and label helpers. Do not import `data/puppies.ts` directly: if the data
  later moves to a database, only `lib/puppies.ts` changes.
- Contact details and the site URL come from `siteConfig` only. Never type a phone number or email in a
  component. WhatsApp links are built with `lib/whatsapp.ts` (`generalWhatsAppLink`, `buildWhatsAppLink`,
  `whatsappMessages.puppy(puppy)`).

### Puppy model notes

- `status`: `"available"` or `"gone"`. 15 puppies are available, 27 have gone home.
- `origin`: `"imported"` or `"local"` (the "In Dubai" showroom). Today every available puppy is imported, so
  `/puppies?origin=local` correctly shows the empty state.
- `gender`: `"male" | "female" | "male-female"`. The Boys/Girls filter treats a pair as matching both.
- `breeds` (filter slugs) is only filled for available puppies; gone puppies are never filtered.
- Unnamed puppies have `name === breed` (for example "Maltipoo"); `hasOwnName()` tells them apart.
- `media[0]` is always an image (the cover). Videos carry a `poster` image. Use `focalPosition()` for
  `object-position` so faces stay inside the crop.

## 2. Rendering strategy

Everything is **statically generated at build time**; there is no server-side data and no per-request work.

- Static pages (`/`, `/puppies`, ...) are prerendered automatically.
- `/puppies/[slug]` uses `generateStaticParams` (one HTML page per puppy, 42 in total) with
  `dynamicParams = false`, so an unknown slug is a 404 rather than being rendered on demand.
- `generateMetadata` builds each puppy's title and description from its data.
- `sitemap.ts` and `robots.ts` are generated from the same data.

**Cache Components is off on purpose.** `create-next-app` enabled `cacheComponents` and `partialPrefetching`;
we removed them in `next.config.ts`. They add a second model (a static shell plus streamed dynamic parts, and
routes kept "hidden" with React `<Activity>` on navigation) that this fully static site does not need, and the
hidden-route behaviour would complicate scroll listeners and dialogs. Without it a page is plain static HTML
and effects clean up on navigation as usual.

> This repository uses Next.js 16, which differs from older versions in places. `params` is a Promise
> (`const { slug } = await params`), `PageProps<"/route">` and `LayoutProps` are global types generated by
> `next typegen` (run by `dev` and `build`), and `next/image` uses `preload` instead of `priority`.
> The bundled docs are in `node_modules/next/dist/docs/`.

## 3. Server vs client components

Default to **server components** (no directive). They ship no JavaScript and can read data directly. Add
`"use client"` only when a component needs state, effects, event handlers or browser APIs.

Client components today:

| Component                               | Why it must be a client component                           |
| --------------------------------------- | ----------------------------------------------------------- |
| `SiteHeader` (+ `useHeaderScrollState`) | Reads the pathname and listens to scroll                    |
| `MobileMenu`                            | Controls a `<dialog>` (`showModal`, Esc, closing animation) |
| `SmoothScroll`                          | Starts Lenis in an effect                                   |

Everything else (footer, action bar, buttons, Teddy, cards) is a server component. Keep the client boundary as
low as you can: a page should stay a server component and import a small client component for the interactive
part (for example the filter chips), not the other way round.

`/puppies` filters are synced to the URL (`?origin=imported&breed=maltipoo&gender=male`). Read them with
`useSearchParams` inside a client component wrapped in `<Suspense>` (required for static prerendering), then
call `filterPuppies`. The prerendered HTML contains all puppies; filtering happens in the browser.

## 4. Styling approach

1. **Tailwind utilities first**, in the JSX, for layout, spacing and typography.
2. **Design tokens** live in `src/styles/theme.css` (`@theme`): colours (`bg-cocoa`, `text-toffee-deep`,
   `border-milk/30`), easing (`ease-pounce`, `ease-silk`, `ease-snap`) and the three font families. Use these
   instead of raw hex values. The few literal colours the original uses (WhatsApp green, footer night, paper)
   are tokens too (`bg-whatsapp`, `bg-night`, `bg-paper`).
3. **Custom utilities** (`src/styles/utilities.css`): `font-plush` (chunky Fraunces headings), `font-plush-text`,
   `font-scrawl` (handwriting), `text-giant | huge | big | lede`, `gutter`, `max-w-page`, `link-ink`,
   `bg-lattice`, `sr-only-focusable`.
4. **Component classes** (`src/styles/components.css`, in `@layer components`): `btn` variants, `chip`,
   `board`, `paper`, `arch`, `scene`. Use `<Button>`, `<Chip>` and `<Section>` rather than writing these classes
   by hand. Being in a layer, a utility on the same element (`min-h-12`, `shadow-none`) wins without `!important`.
5. **Plain CSS only where utilities fall short**: data-attribute states, pseudo-elements, keyframes,
   clip-paths. See `src/styles/shell.css` for the pattern (BEM-like names such as `site-header__hem`). For a
   page, add `src/styles/pages/<page>.css` and `@import` it in `globals.css`. Note that CSS outside a
   `@layer` beats utilities, so do not put a utility and a plain-CSS rule for the same property on one element.
6. `cn()` (`lib/utils.ts`) joins class names. It is `clsx` only; there is no tailwind-merge because it does not
   know our custom utilities and could drop them.

Responsive breakpoints are Tailwind's defaults (`sm 640`, `md 768`, `lg 1024`, `xl 1280`). The header and menu
use `lg` for desktop nav and `md` for the WhatsApp button and the hiding of the sticky mobile bar.

Page-level CSS variables (`base.css`): `--gutter` (side padding), `--header-h` (76px, 64px on phones) and
`--bar-h` (height of the sticky bar on phones, 0 elsewhere). `<main>` is padded by `--header-h`; the footer pads
itself by `--bar-h`. Anchor links use `scroll-padding-top` so headings are not hidden under the header.

`overflow-x: clip` (not `hidden`) is used on `html` and `body` so `position: sticky` still works for the pinned
home sections. `scrollbar-gutter: stable` reserves the scrollbar width (this is why headless screenshots of the
original show a 15px strip on the right).

## 5. Shared pieces and when to use them

| Need                                  | Use                                                                                 |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| Centred page column with side padding | `<Container>` (pages use `pt-10 pb-24 md:pt-16`)                                    |
| Inner-page heading                    | `<PageHeader title kicker lede actions>`                                            |
| Home scene with a sky gradient        | `<Section scene="paths" ...>` (names in `ui/Section.tsx`)                           |
| Button / link styled as a button      | `<Button variant="primary" \| "ghost" \| "whatsapp" href=...>`                      |
| Handwritten line                      | `<HandwrittenLabel tone="ink" \| "soft" \| "inherit">`                              |
| "Available" / "gone home" label       | `<StatusTag status variant="sticker" \| "chip" \| "stamp">`                         |
| Honey pill, "video" pill              | `<Chip>`, `<VideoPill>`                                                             |
| Scalloped edge (quilt, curtain)       | `<ScallopEdge fill flip>`                                                           |
| Mascot                                | `<Teddy pose="peek" \| "walk" \| "sit" \| "sniff" \| "snug" \| "bow" facing label>` |
| Icons and doodles                     | `decor/icons.tsx`, `decor/Doodles.tsx`                                              |
| Diamond lattice background            | `bg-lattice` (set `--lattice-bg` to change the base colour)                         |
| Ink-style cards                       | `.board`, `.paper`, `.arch` classes                                                 |

`<Teddy>` is one SVG split into named parts (`data-p="head"`, `"tail"`, ...). A pose is a small table of
numbers in `Teddy.tsx`; `sniff` is an approximation because the original never showed it in a snapshot. For
the moving mascot later, reuse the same parts and drive `transform` per frame.

## 6. Layout shell

`app/layout.tsx` renders, in order: `SkipLink`, `PageTransition` (placeholder), `SmoothScroll`, `SiteHeader`,
`<main id="main">`, `SiteFooter`, `MobileActionBar`. Pages render only their own content.

- **Header** states are data attributes written to the DOM by `useHeaderScrollState` (not React state, to avoid
  a re-render on every scroll event): `data-scrolled` after 8px, `data-hidden` when scrolling down past 220px,
  and `data-home` (set by React) on `/`. CSS in `shell.css` turns those into the transparent-then-milk header,
  the scalloped hem and the slide-away.
- **Mobile menu** is a native `<dialog>` opened with `showModal()`. Closing sets `data-closing` so the reverse
  circle animation plays, then calls `close()`. Esc, the Close button, a click on a link, a backdrop click and a
  route change all go through the same `close()`.
- **Footer** is static markup. The year is computed at build time.
- **Lenis** only starts for mouse pointers without reduced motion; dialogs are excluded from smooth scroll.
- **Cursor**: the paw cursor is pure CSS in `base.css` (mouse pointers only). The canvas paw trail from the
  original is not built.

## 7. Conventions

- One component per file; the file starts with a one-line comment saying what it is. Comments explain _why_,
  not what the code obviously does.
- Named exports for components; default exports only where Next requires them (pages, layouts, `sitemap`).
- Import with the `@/` alias (`@/components/ui/Button`), never long relative paths.
- Component props are typed with an `interface`/`type` declared next to the component.
- Page metadata: `export const metadata = pageMetadata("faq")` for static pages (title/description come from
  `data/pageMeta.ts`), `generateMetadata` for dynamic ones. The root layout adds the " | TeddyPups U.A.E." suffix.
- Images: use `next/image` with an accurate `sizes`, `alt` from the data, and `focalPosition` for
  `object-position`. Videos: `muted loop playsInline`, with the `poster`.
- Scroll-driven CSS (`animation-timeline: view()`) must sit behind `@supports (animation-timeline: view())`
  with a sensible static fallback. Respect `prefers-reduced-motion` (the base layer already shortens all
  transitions and animations).
- Do not submit or call the original site's forms, `/admin` or `/api`.

## 8. Known gaps (left for the page builders)

- `PageTransition` is an empty placeholder; the spec for the route curtain is in DESIGN-SPEC 2.9 (the running
  puppy artwork is `research/assets/svg/curtain-runner-01.svg`).
- The live Teddy actor that walks along the page, the paw-trail canvas and the home JSON-LD are not built.
- Hash links on the same page use the browser's native jump; Lenis `anchors` is not enabled.
- All routes are placeholders built from `PageHeader`; `not-found.tsx` is a simple stand-in for the "LOST" poster.
