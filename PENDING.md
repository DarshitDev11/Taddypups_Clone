## 5. Conventions and gotchas

- Data only through `@/lib/puppies` helpers; contact info only through `src/data/siteConfig.ts` and `src/lib/whatsapp.ts`.
- Page CSS lives in `src/styles/pages/<page>.css`, imported in `src/app/globals.css`. Class prefixes per page (`home-`, `tp-`...). Use `cn()` from `src/lib/utils.ts`.
- Client components are kept small (header, menu, smooth scroll, curtain, filters, galleries, forms); pages stay server components.
- **After adding a new `@import` to `globals.css`, restart `next dev`** (and sometimes `rm -rf .next`) or the CSS won't appear.
- **Don't run `pkill -f "next ..."`** from a shell: it matches and kills the shell itself. Kill by PID (`ss -ltnp | grep :<port>`).
- A stale `next start` on a port serves an old build → pages look unstyled (CSS 500). Kill it before re-testing.
- Commit messages end with a `Co-Authored-By:` line for the model that wrote them.
- **Token economy (user's preference):** do small/medium tasks directly; use sub-agents only for big separate chunks, at medium effort; one screenshot comparison pass per section, cropped, not repeated loops.
